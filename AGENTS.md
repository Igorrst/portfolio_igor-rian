# Diretrizes do projeto

- Manter o código limpo, legível, organizado e separado por responsabilidade.
- Não usar `any`.
- Não adicionar comentários ao código.
- Não criar código, arquivos, componentes ou dependências desnecessários.
- Verificar se algo equivalente já existe antes de criar uma implementação.
- Preservar a arquitetura, a organização, o design e os padrões existentes do projeto.
- Reutilizar os tokens de design existentes sempre que aplicável.
- Usar somente as tecnologias e convenções adotadas pelo projeto.
- Trabalhar com critérios de front-end sênior sem comprometer a simplicidade da leitura.
- Fazer apenas o que foi solicitado e comunicar somente informações importantes.
- Não publicar, enviar, fazer commit ou push das alterações. O usuário testará e publicará manualmente.
